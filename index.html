HTTP Emulators
Repo apolskiy/PublicAP
Tagline Lightweight HTTP Emulators & Service Mocking for Deterministic QA
Overview A repository of lightweight HTTP service emulators engineered to simulate backend behaviors, custom network conditions, dynamic response headers, and edge-case response codes for deterministic system qualification.
Flask Error Code Emulator
  • Custom Status Code Simulation: Configurable response emulator capable of dynamically reproducing standard, client, and server-side HTTP error states for downstream fault tolerance testing.
  • Supported Error Codes & Statuses:
    • 4xx Client Errors: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 405 Method Not Allowed, 406 Not Acceptable, 408 Request Timeout, 409 Conflict, 410 Gone, 411 Length Required, 412 Precondition Failed, 413 Request Entity Too Large, 414 Request-URI Too Long, 415 Unsupported Media Type, 416 Requested Range Not Satisfiable, 417 Expectation Failed, 419 Insufficient Space on Resource.
    • 5xx & Custom Errors: 500 Internal Server Error, 501 Not Implemented, 503 Service Unavailable, 600 Custom Error.
  • Source: PublicAP/flask_app
  • Docker Image: apolskiy/flask_app on Docker Hub
Custom Header & Verb Response Emulator
  • Dynamic Header Reflection: Accepts and echoes custom HTTP response headers specified directly by the requester in real-time.
  • Full HTTP Verb Support: Supports GET, POST, PUT, PATCH, and DELETE requests for comprehensive REST API state testing.
  • Server Lifecycle Control Codes: Special status codes drive the server during automated runs: 590 sleeps the server for 120 seconds, 591 stops the service and restarts it after 60 seconds, and 592 shuts the service down.
  • Input Validation: 999 is the default error returned when parameters are invalid or out of range, responding with an internal server error.
  • Source: custom_header_response_to_http_request.py
Tech Stack Python, Flask, HTTP/S, REST APIs, Curl, Docker, Linux
